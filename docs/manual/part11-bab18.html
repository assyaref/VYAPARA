Bab 18 — Pembaruan Aplikasi, Dashboard Pemilik & Deployment Server

18.1 Pembaruan Aplikasi (Auto-Update)

  1. Instalasi rilis baru otomatis terdeteksi melalui GitHub Releases (owner: assyaref / repo: VYAPARA).
  2. Buka Pengaturan → Pembaruan Aplikasi untuk melihat versi terpasang dan memeriksa pembaruan baru.
  3. Klik Periksa Pembaruan — jika ada rilis baru, status berubah menjadi Baru.
  4. Klik Unduh & Pasang — progress download tampil — lalu klik Restart & Pasang; aplikasi tertutup & membuka versi baru.
  5. Tanpa jaringan, periksa pembaruan menampilkan pesan “Update check gagal …” — aplikasi tetap berjalan normal.
Catatan rilis: pemilik membuat rilis di GitHub dengan file VYAPARA-Setup-<versi>.exe (nama file harus cocok dengan artifactName di package.json). Auto-update hanya bekerja pada aplikasi terinstal (production), bukan electron:dev.

18.2 Installer Distribution Pipeline

  1. Jalankan node scripts/build-installer.mjs — pipeline selalu menjalankan: vite build → electron-builder (NSIS) → checksum SHA-256 ke release/SHA256SUMS.txt.
  2. Mode default unsigned — Windows menampilkan SmartScreen untuk pengguna baru.
  3. Bila sudah memiliki sertifikat Authenticode: set CSC_LINK & CSC_KEY_PASSWORD, lalu jalankan ulang — installer ditandatangani otomatis. Set SIGNING_REQUIRED=true untuk menolak build unsigned. Lihat SIGNING.md.

18.3 Owner Web Dashboard — Multi-Outlet

  1. Owner dashboard tersedia di https://<host-sync>/admin — self-contained, tanpa aset eksternal.
  2. Gambar: token SYNC_ADMIN_TOKEN (dari .env server) → halaman menampilkan: total outlet, perangkat aktif, event diterima, konflik/duplikat, detail per outlet, jenis event teratas, daftar perangkat terdaftar.
  3. Refresh otomatis tiap 10 detik; token hanya disimpan di memori (hilang saat tab ditutup).
  4. Semua endpoint /admin/api/* dilindungi Bearer token; tanpa token → 401.
Penting: dashboard tidak bisa menghitung omzet rupiah toko (server sync tidak menyimpan data penjualan, hanya metadata sync). Dashboard memantau kesehatan & aktivitas replikasi — omzet & laporan finansial tetap dari aplikasi desktop tiap outlet.

18.4 Mendeploy Sync Server (Staging/Production)

  1. Siapkan VPS Linux + Docker. Salin repo ke server (atau gunakan image bawaan).
  2. docker build -f deploy/Dockerfile -t vyapara-sync . — image self-contained; bundle dibangun dari source di dalam build (esbuild alias, tanpa npm workspaces).
  3. Salin deploy/.env.example → .env → isi SYNC_ENROLLMENT_SECRET & SYNC_ADMIN_TOKEN (openssl rand -hex 32) & SYNC_DB_PATH=/data/sync-server.db & PORT=8787.
  4. docker compose up -d --build → verifikasi: curl http://127.0.0.1:8787/v1/sync/health → {"ok":true}.
  5. TLS via nginx — template deploy/nginx.conf + certbot; jangan buka port 8787 ke publik.
  6. Jalankan staging acceptance sesuai DEPLOY.md §6 sebelum produksi; catat hasilnya di laporan phase Anda.
Batasan: Docker image yang dibuat di mesin ini hanya diuji lokal — smoke test health + /admin + /admin/api/overview LOLOS, tetapi belum diuji pada VPS sungguhan. Deployment & monitoring publik tetap menjadi tugas Anda; lihat deploy/DEPLOY.md.
